    14→## 0 · Change summary (v1.0 → v3.0) *(unchanged, kept for history)*
    15→
    16→| Area | Change | Why (trade-off) |
    17→|---|---|---|
    18→| Data model | Per-frame duplicated layer stacks → **per-clip layer stack + per-frame cels** (+ optional linked cels) | Prototype stores every layer in every frame (name-matched fallbacks already required — fragile, storage ×frames). Cels are the Aseprite/Godot standard. Serialized v1 import kept for compatibility. |
    19→| History | Full-layer buffer snapshots (limit 40) → **typed command bus + 16×16 tile-diff entries**, memory budget, undo depth ≥ 250 typical strokes | Prototype caps at 40 because buffers are expensive; tile diffs make deep history cheap. Trade-off: slightly more complex commit path — mitigated by keeping the existing begin/endStroke API shape. |
    20→| Tools | Added: marquee/selection ops, ellipse, pixel-perfect strokes, dither fill, transform ops, palette enforcement | Matches the plan's own "pixel-precise editing" promise; prototype verified missing (§10). |
    21→| AI pipeline | Naive NN contain-fit → **normalize pipeline v2** (trim → dominant-color downscale → alpha threshold+despeckle → OKLab quantize → optional outline cleanup) + candidates, presets, cache, cost meter | Prototype pipeline verified working but produces muddy edges on busy art; v2 is deterministic and free. |
    22→| Animation | **Deterministic part-based motion presets as the flagship animation feature**; per-frame durations; loop modes; flicker QA; img2img variations only as Tier-2 review-gated | Directly implements v1 §05 "iterative modifications over independent generation" with an actual mechanism. |
    23→| MCP | 9 REST endpoints → **real MCP server (Streamable-HTTP + stdio proxy)**, pairing, 4 permission tiers, approval queue, same command bus as UI | The differentiator deserves the full spec; REST catalog + zod schemas port almost 1:1. |
    24→| Files | Prisma/SQLite (web) → **`.pixelforgeproj` ZIP format**: atomic save, journal, backups, provenance, thumbnails | Desktop-first requirement; SQLite stays behind as web-testbed only. |
    25→| Export | PNG/sheet/JSON (kept) + **GIF** + **Godot SpriteFrames `.tres`** promoted to P1 | "Godot-friendly" is a page-1 promise; `.tres` is a text template — cheap. |
    26→| Security | Settings keys in localStorage plaintext → OS-keychain-backed encryption via safeStorage, scoped FS, CSP | Desktop attack surface differs from web. |

    36→### Check ① — Project JSON schema vs per-clip layer stack / per-frame cel architecture
    37→**Verdict: v3.0 schema contradicted its own model — fixed.**
    38→
    39→| # | Problem in v3.0 | Correction in v3.1 |
    40→|---|---|---|
    41→| C1 | §6 `project.json` declared `layers` at **project top level**, but §2.4 specifies the layer stack "defined ONCE **per clip**". As written, all clips would share one stack — clips could not have different layer counts/names, breaking the cel model and the v1 importer. | `layers[]` moved **inside each clip** (`clip.layers`). Cel paths unchanged (`cels/<clipId>/<frameId>/<layerId>.png`). New clips default to one layer "Layer 1". §6 schema updated to match §2.4 exactly. |
    42→| C2 | Cel entries were bare path strings (`"ly1": "cels/…png"`), so **linked cels** (§2.4 `layer.linked`) had no defined representation — which file does frame N reference? | Cel entry upgraded to object `{ "src": <path>, "linked": true? }`. Rule: a linked layer stores **one** PNG at `cels/<clipId>/shared/<layerId>.png`; every frame's cel for that layer points to the same `src`. Editing any frame's linked cel edits the shared buffer (matches §2.4 "edit once applies everywhere"). |
    43→| C3 | v1 prototype `Clip.loop` is a **boolean** (`types.ts`), v2 only defined `loopMode: forward\|reverse\|pingpong`. The v1 migration for `loop:false` ("play once") was undefined — silent semantic loss. | Per-clip **`loop: boolean` + `loopMode` enum** both serialized. Godot `.tres` maps both cleanly (`loop` property per animation). |
    44→| C4 | §4.1 part tags ("Tag part" regions) had **no home in the file format** — presets could not be saved/reloaded. | `clip.parts[]` added to schema: `{ id, name, layerId, rect?, anchorFrameId, z }` (rect omitted = whole layer is the part; `z` = paint order).     45→| C5 | Trash model (see C9) and manifest coverage were underspecified. | `project.trash[]` added: `{ kind:'frame'\|'layer'\|'clip', clipId?, payload, deletedAt }`, cap 20 items (oldest purged on overflow). `manifest.checksums` explicitly covers **all** ZIP entries (project.json, every cel/thumb PNG, journal). |
    46→| C6 | Desktop autosave cadence was unspecified (prototype autosaves every 2.5 s to SQLite; desktop writes files). | Defined: autosave default **30 s** (setting 10–120 s) → writes `<file>.autosave.pixelforgeproj` via temp+rename; backups every 10 min if dirty, keep 5 (unchanged). |

    67→### Check ④ — Part-based preset edge cases (overlap, transparency, gaps, alignment)
    68→**Verdict: v3.0 defined the curves but not the composition semantics — now fully specified.**
    69→
    70→| # | Problem in v3.0 | Correction in v3.1 |
    71→|---|---|---|
    72→| C14 | Nothing defined: what happens when part rects **overlap**, how **transparency** behaves, what fills **pixel gaps** vacated by movement, how generated frames **align** with existing frames, or how presets interact with **linked cels**. | New §4.1.1 "Composition semantics" with rules R1–R10 (R10 added by C15): painter's-order cut-then-paste per part (z-order = parts array order); overlap pixels owned by the **higher-z** part (tag tool warns on overlap); alpha **≥128 = opaque** (moves), <128 = transparent (consistent with normalize v2 threshold); transforms are **integer-pixel**, regions clipped at canvas edge (no wrap — wrap remains a Move-tool-only mode); vacated-px handling via per-preset `gapFill: 'none' (default) \| 'edge-extend'` (repeats the trailing boundary row/column until the vacated strip is filled — see C26) — presets produce draft frames, manual touch-up expected (honest scoping); presets **skip linked layers** (background must not bob), or unlink-with-undo if explicitly targeted; generated frames derive from the **anchor/reference frame** so all frames stay aligned (same absolute rects each frame — per-frame deltas are Tier-2's job, not presets'); frame-count reconciliation: new-clip target sized exactly, overwrite target pads by holding the reference or trims only with `overwrite:true`; generated cels get `durationMs: 0` (use clip fps); pixels **outside part rects are bit-identical** to the source (static remainder untouched). |
    73→| C15 | Curve table was calibrated on 32×32 with no rule for other canvas sizes — amplitude would be wrong (invisible at 16×16, cartoonish at 64×64). | Scaling rule: `ampScale = clipHeight / 32`; per-frame offset = `sign(v) · max(1, \|round(v × ampScale)\|)` for every non-zero curve value v (magnitude floor 1 px at small sizes, **direction preserved** — see C25). Deterministic → golden-testable. |

   143→### 2.2 Pixel-perfect drawing
   144→Freehand strokes are recorded as points, then plotted via Bresenham **with L-decimation** (above). Brush >1 px bypasses decimation. Verified as the #1 Aseprite-feel gap in the prototype.
   145→
   146→### 2.3 Palette management & enforcement
   147→- HSV picker with recent colors + shade/tint ramps (prototype has hex + swatches only).
   148→- **Enforcement mode** (project setting, default on): drawing/quantize replaces any out-of-palette color with nearest palette entry (OKLab distance); a status-bar chip shows "out-of-palette: N px" when off.
   149→- Palette import/export: `.gpl`, JASC `.pal`, Aseprite `.hex` (P1). Auto-extract palette from canvas (median cut, ≤64) — **already implemented** in `color.ts quantizeBuffer` (reused).
   150→- Palette ops as commands (undoable): add/remove/reorder/replace-global-color (replace-color = deterministic cel-wide recolor, P1).
   151→
   152→### 2.4 Layers & per-frame cels (model change)
   153→```
   154→Project
   155→├─ settings, palette, trash[]                         ← trash: deleted frames/layers/clips (C5)
   156→└─ Clip (id, name, fps, loop, loopMode, tags[])
   157→   ├─ LayerStack: Layer[] (bottom→top)   ← defined ONCE PER CLIP (C1)
   158→   ├─ Parts: Part[] (optional motion regions, C4)
   159→   └─ Frame[] ─ each holds Cel per layer
   160→       Cel { src: pngPath, linked? }                  ← missing cel = fully transparent (C2)
   161→Layer { id, name, visible, opacity, linked? }
   162→Part { id, name, layerId, rect?, anchorFrameId, z }
   163→```
   164→- **Linked cels**: a layer can pin all frames to one cel (backgrounds) — cuts storage and "edit once applies everywhere." Stored at `cels/<clipId>/shared/<layerId>.png`; every frame references the same `src` (C2). **Phase scope (C19): P0 = format + engine support; P2 = UI toggle.**
   165→- **Parts** serialize as regions, never as cuts; overlap pixels are owned by the highest-z part (composition rules in §4.1.1).
   166→- Migration: import SerializedProject **v1** (per-frame layers, `loop: boolean`) → v2 cels by matching layer ids; loop mapping per C3; v1 read support permanent. New clips default to a single layer "Layer 1".
   167→- Layer ops (already in prototype, re-targeted to the clip's stack): add, delete (trash-backed), duplicate, merge down (composites cel-wise per frame), reorder, opacity/visibility/name.
   168→
   169→### 2.5 Undo/redo — command history spec
   170→- **Command envelope** `{ id, type, payload, label, timestamp, origin: 'ui'|'mcp'|'ai', undo(): Patch, redo(): Patch }` — MCP and AI call the exact same bus (v1 §03 separation-of-concerns, enforced in code).
   171→- **Pixel edits**: 16×16 **tile diffs** (dirty tiles with before/after bytes), stroke-grouped via existing `beginStroke/endStroke/cancelStroke` contract. Structural edits: shallow snapshots with copy-on-write buffers (prototype mechanism, kept).
   172→- **Budget**: default 64 MB per project (Settings; 16–512); oldest entries evicted; status bar shows usage. Typical 32×32 stroke ≈ 1–8 KB → **≥ 250 undos guaranteed, typically thousands** (C21) vs prototype's 40 full-buffer entries.
   173→- UI: Undo/Redo buttons (exist) + History panel (P2) with jump-to-state.
   174→
   175→### 2.6 Onion skinning & playback
   176→- Onion: previous/next N (1–3), opacity 25/50%, red/green tint; **prototype's single toggle → configurable** (prev-1 default).
   177→- Playback: fixed-step accumulator + rAF (prototype pattern kept); **`loop: boolean` + loopMode `forward | reverse | pingpong`** (C3: `loop:false` = play once through, stop on last frame in the mode's direction); **per-frame `durationMs` override** (0 = use clip fps); scrubbing + `,` / `.` frame step; **Enter = play/pause** (C17).

   199→## 3 · AI generation system
   200→
   201→### 3.1 Provider adapter (evolved from prototype's verified adapter)
   202→```ts
   203→interface AIProvider {
   204→  id: string; kind: 'zai'|'openai-compatible'|'anthropic'|'local'
   205→  capabilities: { img2img: boolean; seed: boolean; mask: boolean; n: boolean }
   206→  generate(req: GenRequest): Promise<GenResult>   // images, cost estimate, timings
   207→  editImage?(req: EditRequest): Promise<GenResult> // img2img / inpaint when supported
   208→}
   209→```
   210→- Ships: **Z.AI built-in**, **OpenAI-compatible** (OpenAI, Gemini OpenAI-dialect, OpenRouter, local ComfyUI/OpenAI-shims) — prototype's dialects verified; **Anthropic** stays chat-only (verified: no image API).
   211→- **API key storage (C13 — exact mechanism):** keys live only in the **main process**. Renderer submits a key once via bridge (`settings.setApiKey`); main encrypts with **Electron `safeStorage`** (DPAPI on Windows, Keychain-backed on macOS, libsecret/kwallet on Linux) and persists **base64 ciphertext** as `apiKeyEnc` in the settings file. Plaintext is never written to disk and never returned to the renderer — the bridge exposes only `settings.hasKey(providerId)` (boolean) and `settings.removeKey`. If `safeStorage.isEncryptionAvailable()` is false (e.g., Linux without a keyring service), keys are kept **in memory for the session only** with a persistent warning — no plaintext disk fallback. The web prototype's plaintext localStorage keys are **not** auto-imported (different app; one-time re-entry). Job runner decrypts in memory per request.
   212→- **Job manager** (main process): queue `queued → generating → normalizing → review`, cancel, timeout (120 s, verified needed), retry, concurrency 1 per provider; spend meter + monthly cap; every job logged with model/params/duration.
   213→
   214→### 3.2 Generation flow (candidates, never silent replace — v1 principle, verified implemented, kept)
   215→1. Prompt (+ recipe preset: size, palette, style tags, seed, provider) → 2. generate N thumbnails (n=1–4 when supported; else N jobs) → 3. pick → full-res → 4. **normalize v2** → 5. review dialog (original vs normalized, zoom, re-run with tweaks) → 6. **Import as layer / as new frame / discard** (prototype's three actions, kept verbatim).
   216→- **Cache**: `hash(recipe + seed + model + prompt)` → hits cost nothing; generation history persisted per project (thumbnails + provenance), restorable.
   217→- **Cost controls**: pre-flight estimate ("≈ $0.04 · gpt-image-1"), monthly cap with hard stop, "dry run" showing the exact prompt.
   218→
   219→### 3.3 Deterministic normalize pipeline v2 (replaces prototype's contain-fit NN)
   220→Order matters; each step pure & unit-testable (golden-image tests):
   221→1. **Trim** to content bbox (alpha/color border flood).
   222→2. **Dominant-color grid downscale** to target WxH: per target cell take the modal color of the source block (center-weighted, ties → closest to block mean). *Why not plain NN (prototype):* NN aliases detail into noise on downscale >2×; dominant-color yields clean sprite reads. (A/B test gated in P1, §9 benchmarks.)
   223→3. **Alpha threshold** (<128 → 0) + **despeckle** (remove isolated single opaque px).
   224→4. **Background removal**: border flood-fill with tolerance (prototype algorithm, kept, already good).
   225→5. **OKLab quantize** to project palette (or auto median-cut ≤64 when "free palette"); dithering **off** by default.
   226→6. Optional 1-px outline cleanup (remove AA fringe: out-of-palette px adjacent to transparency).
   227→All steps run off the main thread (Worker). Provider-independent ⇒ identical output across providers, free to re-run. The <128 alpha threshold here is the same binary-alpha rule the motion composer relies on (§4.1.1 R3).
   228→
   229→### 3.4 Provenance
   230→Every candidate stores `{model, providerId, prompt, seed?, params, timestamp, jobDurationMs}` — shown in review UI, persisted in project file (`provenance/ai/`), reused by "regenerate similar."

   234→## 4 · AI animation — realistic workflow
   235→
   236→> Preserved from v1.0: no promise of one-prompt production animation. **Mechanism below is the v3 addition; composition semantics formalized in v3.1 (C14/C15).**
   237→
   238→### 4.1 Tier 1 — Part-based motion presets (flagship, P1)
   239→- Character = base sprite; optional **part tags** (head/body/armL/armR/legL/legR) via marquee → "Tag part" (stores region, not a cut). Parts may also be separate layers (AI can generate part variants) — a part with no `rect` spans its whole layer.
   240→- Parts serialize at **clip scope** (`clip.parts[]`, C4): `{ id, name, layerId, rect?, anchorFrameId, z }`; array order = paint order (z override optional). Tagging warns when the new region overlaps an existing part.
   241→- Presets = parametric transform curves per part, composed into new cels:
   242→| Preset | Frames | Curve (32×32 reference, scales per C15) |
   243→|---|---|---|
   244→| idle-bob | 4 | body dy = [0,−1,−2,−1]; head dy = body; hair/coat 1-frame lag |
   245→| walk | 4/6/8 | legL/legR alternate dx ±3, dy [0,−1]; body bob dy [0,−1,0,1]; arm counter-swing |
   246→| run | 6 | walk amplitude ×1.5, forward lean dx +1, dy arc |
   247→| attack | 4–6 | armL arc keyframes (raise→swing→recover), 1-px smear frame option |
   248→| jump | 6 | dy parabola, squash [1,2] px on takeoff/land |
   249→- **Composition is undoable, deterministic, $0**; every generated frame remains a normal editable cel; presets can be re-applied/re-parameterized ("amplitude", "hold frames", `gapFill`).
   250→- Verification hooks: side-by-side before/after, per-frame diffs.
   251→
   252→#### 4.1.1 Composition semantics (v3.1, C14/C15)
   253→The composer is a pure function `(sourceCel, parts, preset, params, frameIndex) → cel` — golden-tested, runs in core with zero DOM. **Absent parts**: preset curves referencing part names that are not tagged on the clip are silently skipped for that part (e.g., idle-bob's "hair 1-frame lag" is a no-op on a head/body-only farmer); the apply report lists every skipped part (C27).
   254→
   255→- **R1 · Paint order**: process parts bottom→top (parts array order / `z`). For each part: (a) **cut** its owned pixels from the working canvas (set transparent), (b) apply the frame's integer offset, (c) **paste** back. Later (higher-z) parts therefore always win overlaps — head covers body at the neck, arms cover torso.
   256→- **R2 · Ownership**: a pixel belongs to exactly one part — the **highest-z part whose rect contains it** (assigned at tag time; the tag tool warns on overlap). Lower parts never move pixels they don't own, so overlaps never double-draw.
   257→- **R3 · Transparency**: alpha **≥ 128 = opaque** (moves with the part); alpha < 128 = transparent (stays cleared). This matches normalize v2's binary-alpha threshold (§3.3 step 3); AI-generated or hand-painted semi-alpha px are thresholded by the same rule before composition.
   258→- **R4 · Bounds & gaps**: offsets are **integer pixels**; translated regions are **clipped at the canvas edge** (pixels pushed outside are dropped — no wrap; wrap remains Move-tool-only). Pixels vacated by a part's move are handled by the preset's `gapFill` mode: **`none` (default)** leaves them transparent (honest draft; artist touches up — consistent with "presets propose, humans approve"), **`edge-extend`** fills the entire vacated strip by **repeating the trailing boundary row/column** of the pasted region until the hole is closed (1–3 px at reference amplitudes — prevents see-through slivers on bob/walk/run).
   259→- **R5 · Frame alignment**: every generated frame derives from the **anchor/reference frame** (default frame 1; `anchorFrameId` per part). The same absolute rects and per-frame offsets are used for every output frame, so frames cannot drift apart. Existing per-frame pixel variation is intentionally *not* preserved by presets — that is Tier-2's job (§4.2). Output frames are full replacements of the target cels.
   260→- **R6 · Frame-count reconciliation**: targeting a **new clip** → sized exactly to the preset (4/6/8). Overwriting an existing clip with `overwrite: true` → if the clip has fewer frames, missing frames are appended as holds of the reference; if more, extra frames are left untouched. Either way it is one undoable command.
   261→- **R7 · Timing**: generated cels get `durationMs: 0` → inherit clip fps (consistent with §2.6). Loop behavior follows the clip's `loop`/`loopMode` (C3).
   262→- **R8 · Linked cels**: presets **skip linked layers** (a pinned background must not bob). If a part explicitly targets a linked layer, applying the preset **unlinks** it first (recorded in the same undo entry).
   263→- **R9 · Static remainder**: pixels outside all part rects are **bit-identical** to the source frame — presets never repaint what they don't move (makes per-frame diffs and the flicker detector meaningful).
   264→- **R10 · Cross-canvas scaling (C15, C25)**: `ampScale = clipHeight / 32`; each non-zero curve value v maps to `sign(v) · max(1, |round(v × ampScale)|)` px — magnitude floor 1 px, **direction preserved** (a bob never flips into a sag at 16×16). A 16×16 farmer still visibly bobs (1 px), a 64×64 one moves 2–4 px, matching the reference feel.
   265→
   266→### 4.2 Tier 2 — AI frame variations (P2, review-gated)
   267→img2img: frame N as init (strength 0.25–0.45, seed locked, recipe attached) → normalize v2 → **pixel-diff overlay vs frame N** → user accepts/edits/discards. Suited to breathing/blink/tail-wag deltas. Never auto-chained without review.
   268→
   269→### 4.3 Tier 3 — Experimental (P3, flagged)
   270→Video-model → pixelize pipelines; dedicated pixel-animation services. Behind "Experimental" settings flag; excluded from marketing claims.
   271→
   272→### 4.4 Consistency QA tools (P1)
   273→- **Reference lock**: pin frame 1 as ghost + baseline guide + facing arrow; every new frame request auto-attaches it.
   274→- **Flicker detector**: per-frame pixel-diff heatmap + "jitter score" (changed-px count vs threshold); failing frames highlighted in timeline. Because of R9, diff noise from the composer itself is zero — detected flicker is real content flicker.
   275→- **Anchor overlay**: ground line + center axis; onion skins (§2.6).
   276→- **Review workflow**: animation strip view with per-frame accept/revert; nothing enters the clip without explicit commit.

   303→A small class of L1 operations **escalate to an approval card based on document state**:

   425→## 9 · Performance & reliability
   426→
   427→### 9.1 Budgets (C16: reference hardware + CI protocol)
   428→**Reference hardware**: 4-core i5/Ryzen-5 class laptop, SSD, 16 GB RAM (2020 mid-range). **Protocol**: packaged build (not dev mode), median of 10 runs, warm cache; cold start measured main-ready → first paint.
   429→| Metric | Target (reference HW) | Feasibility note |
   430→|---|---|---|
   431→| Open 256×256 × 24-frame project | < 300 ms | Lazy cel decode: only visible frame-1 cels + 64 px thumbs decode at open (~40 small PNGs) |
   432→| Pan/zoom | 60 fps @ 8× zoom | Single drawImage of composited frame; trivial at ≤256² |
   433→| Playback | 60 fps (dirty-rect compositing; onion ≤ 3 skins) | Compose on frame change only |
   434→| Undo memory | ≤ 64 MB default (16–512 setting) | Tile diffs: 32×32 stroke ≈ 1–8 KB → thousands of entries |
   435→| Autosave pause | < 100 ms off-UI-thread, **dirty cels only** (C16) | Unchanged cels never re-encoded |
   436→| Cold start | < 2 s | main-ready → first paint; signed packaged build |
   437→| Installer | < 120 MB | ~30 MB headroom over stock Electron NSIS |
   438→
   439→**CI enforcement (C16)**: absolute numbers are documented targets; CI asserts **relative regression vs a recorded baseline (fail > 1.15×)** — absolute-ms gates on shared runners are flaky by nature.
   440→
   441→### 9.2 Memory & rendering strategy
   442→- Tile-diff history (§2.5); cel PNGs stored once, decoded lazily; LRU decode cache (default 128 MB); Worker compositing for playback/export; dirty-rect repaint (prototype's full-canvas repaint acceptable ≤64×64, replaced above).
   443→- **AI cancellation**: AbortController end-to-end (prototype's 120 s timeout kept; cancel button added); queue jobs drop cleanly at any state.
   444→
   445→### 9.3 Error recovery
   446→Atomic save + journal replay + backups + autosave (§6); export writes temp + rename; crash reporter captures last 100 commands (local); unsaved-changes guard on quit; MCP approval timeout → structured pending (§5.4).
   447→
   448→### 9.4 Testing
   449→- **core unit tests**: command bus (undo round-trip incl. mid-stroke structural edits), pixel ops, normalize golden images, **motion-composer goldens (R1–R10: overlap z-order, gapFill modes, amp scaling on 16/32/64, linked-layer skip, static remainder)**, exporters golden files, file-format migration v1→v2 (incl. loop mapping C3).
   450→- **MCP contract tests**: schema validation per tool, permission-tier enforcement, **dirty-project escalation (C7)**, **trash restore/purge gating (C9)**, approval timeout, pairing.
   451→- **E2E (Playwright over Electron)**: draw→undo→save→kill -9→reopen→identical; generate→review→import; motion preset→edit cel→export.
   452→- **Security tests**: path traversal on save-as/export, token rejection, oversized payloads, loopback-only bind verification, **plaintext-key grep gate (C13)**.
   453→- **Benchmarks**: §9.1 protocol asserted in CI (relative regression harness).
   454→- **Packaging**: electron-builder (NSIS, Win first), code-signing cert pipeline, **electron-updater** staged rollout; crash telemetry opt-in only, local by default.
