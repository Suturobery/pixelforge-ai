    14→    14→## 0 · Change summary (v1.0 → v3.0) *(unchanged, kept for history)*
    15→    15→
    16→    16→| Area | Change | Why (trade-off) |
    17→    17→|---|---|---|
    18→    18→| Data model | Per-frame duplicated layer stacks → **per-clip layer stack + per-frame cels** (+ optional linked cels) | Prototype stores every layer in every frame (name-matched fallbacks already required — fragile, storage ×frames). Cels are the Aseprite/Godot standard. Serialized v1 import kept for compatibility. |
    19→    19→| History | Full-layer buffer snapshots (limit 40) → **typed command bus + 16×16 tile-diff entries**, memory budget, undo depth ≥ 250 typical strokes | Prototype caps at 40 because buffers are expensive; tile diffs make deep history cheap. Trade-off: slightly more complex commit path — mitigated by keeping the existing begin/endStroke API shape. |
    20→    20→| Tools | Added: marquee/selection ops, ellipse, pixel-perfect strokes, dither fill, transform ops, palette enforcement | Matches the plan's own "pixel-precise editing" promise; prototype verified missing (§10). |
    21→    21→| AI pipeline | Naive NN contain-fit → **normalize pipeline v2** (trim → dominant-color downscale → alpha threshold+despeckle → OKLab quantize → optional outline cleanup) + candidates, presets, cache, cost meter | Prototype pipeline verified working but produces muddy edges on busy art; v2 is deterministic and free. |
    22→    22→| Animation | **Deterministic part-based motion presets as the flagship animation feature**; per-frame durations; loop modes; flicker QA; img2img variations only as Tier-2 review-gated | Directly implements v1 §05 "iterative modifications over independent generation" with an actual mechanism. |
    23→    23→| MCP | 9 REST endpoints → **real MCP server (Streamable-HTTP + stdio proxy)**, pairing, 4 permission tiers, approval queue, same command bus as UI | The differentiator deserves the full spec; REST catalog + zod schemas port almost 1:1. |
    24→    24→| Files | Prisma/SQLite (web) → **`.pixelforgeproj` ZIP format**: atomic save, journal, backups, provenance, thumbnails | Desktop-first requirement; SQLite stays behind as web-testbed only. |
    25→    25→| Export | PNG/sheet/JSON (kept) + **GIF** + **Godot SpriteFrames `.tres`** promoted to P1 | "Godot-friendly" is a page-1 promise; `.tres` is a text template — cheap. |
    26→    26→| Security | Settings keys in localStorage plaintext → OS-keychain-backed encryption via safeStorage, scoped FS, CSP | Desktop attack surface differs from web. |

    37→    37→**Verdict: v3.0 schema contradicted its own model — fixed.**
    38→    38→
    39→    39→| # | Problem in v3.0 | Correction in v3.1 |
    40→    40→|---|---|---|
    41→    41→| C1 | §6 `project.json` declared `layers` at **project top level**, but §2.4 specifies the layer stack "defined ONCE **per clip**".     68→    68→**Verdict: v3.0 defined the curves but not the composition semantics — now fully specified.**
    69→    69→
    70→    70→| # | Problem in v3.0 | Correction in v3.1 |
    71→    71→|---|---|---|
    72→    72→| C14 | Nothing defined: what happens when part rects **overlap**, how **transparency** behaves, what fills **pixel gaps** vacated by movement, how generated frames **align** with existing frames, or how presets interact with **linked cels**. | New §4.1.1 "Composition semantics" with rules R1–R10 (R10 added by C15): painter's-order cut-then-paste per part (z-order = parts array order); overlap pixels owned by the **higher-z** part (tag tool warns on overlap); alpha **≥128 = opaque** (moves), <128 = transparent (consistent with normalize v2 threshold); transforms are **integer-pixel**, regions clipped at canvas edge (no wrap — wrap remains a Move-tool-only mode); vacated-px handling via per-preset `gapFill: 'none' (default) \| 'edge-extend'` (repeats the trailing boundary row/column until the vacated strip is filled — see C26) — presets produce draft frames, manual touch-up expected (honest scoping); presets **skip linked layers** (background must not bob), or unlink-with-undo if explicitly targeted; generated frames derive from the **anchor/reference frame** so all frames stay aligned (same absolute rects each frame — per-frame deltas are Tier-2's job, not presets'); frame-count reconciliation: new-clip target sized exactly, overwrite target pads by holding the reference or trims only with `overwrite:true`; generated cels get `durationMs: 0` (use clip fps); pixels **outside part rects are bit-identical** to the source (static remainder untouched). |

   146→   146→### 2.3 Palette management & enforcement
   147→   147→- HSV picker with recent colors + shade/tint ramps (prototype has hex + swatches only).

   152→   152→### 2.4 Layers & per-frame cels (model change)
   153→   153→```
   154→   154→Project
   155→   155→├─ settings, palette, trash[]                         ← trash: deleted frames/layers/clips (C5)
   156→   156→└─ Clip (id, name, fps, loop, loopMode, tags[])
   157→   157→   ├─ LayerStack: Layer[] (bottom→top)   ← defined ONCE PER CLIP (C1)
   158→   158→   ├─ Parts: Part[] (optional motion regions, C4)
   159→   159→   └─ Frame[] ─ each holds Cel per layer
   160→   160→       Cel { src: pngPath, linked? }                  ← missing cel = fully transparent (C2)
   161→   161→Layer { id, name, visible, opacity, linked? }
   162→   162→Part { id, name, layerId, rect?, anchorFrameId, z }
   163→   163→```
   164→   164→- **Linked cels**: a layer can pin all frames to one cel (backgrounds) — cuts storage and "edit once applies everywhere." Stored at `cels/<clipId>/shared/<layerId>.png`; every frame references the same `src` (C2). **Phase scope (C19): P0 = format + engine support; P2 = UI toggle.**
   165→   165→- **Parts** serialize as regions, never as cuts; overlap pixels are owned by the highest-z part (composition rules in §4.1.1).
   166→   166→- Migration: import SerializedProject **v1** (per-frame layers, `loop: boolean`) → v2 cels by matching layer ids; loop mapping per C3; v1 read support permanent. New clips default to a single layer "Layer 1".
   167→   167→- Layer ops (already in prototype, re-targeted to the clip's stack): add, delete (trash-backed), duplicate, merge down (composites cel-wise per frame), reorder, opacity/visibility/name.

   199→   199→## 3 · AI generation system
   200→   200→
   201→   201→### 3.1 Provider adapter (evolved from prototype's verified adapter)
   202→   202→```ts
   203→   203→interface AIProvider {
   204→   204→  id: string; kind: 'zai'|'openai-compatible'|'anthropic'|'local'
   205→   205→  capabilities: { img2img: boolean; seed: boolean; mask: boolean; n: boolean }
   206→   206→  generate(req: GenRequest): Promise<GenResult>   // images, cost estimate, timings
   207→   207→  editImage?(req: EditRequest): Promise<GenResult> // img2img / inpaint when supported
   208→   208→}
   209→   209→```
   210→   210→- Ships: **Z.AI built-in**, **OpenAI-compatible** (OpenAI, Gemini OpenAI-dialect, OpenRouter, local ComfyUI/OpenAI-shims) — prototype's dialects verified; **Anthropic** stays chat-only (verified: no image API).
   211→   211→- **API key storage (C13 — exact mechanism):** keys live only in the **main process**. Renderer submits a key once via bridge (`settings.setApiKey`); main encrypts with **Electron `safeStorage`** (DPAPI on Windows, Keychain-backed on macOS, libsecret/kwallet on Linux) and persists **base64 ciphertext** as `apiKeyEnc` in the settings file. Plaintext is never written to disk and never returned to the renderer — the bridge exposes only `settings.hasKey(providerId)` (boolean) and `settings.removeKey`. If `safeStorage.isEncryptionAvailable()` is false (e.g., Linux without a keyring service), keys are kept **in memory for the session only** with a persistent warning — no plaintext disk fallback. The web prototype's plaintext localStorage keys are **not** auto-imported (different app; one-time re-entry). Job runner decrypts in memory per request.
   212→   212→- **Job manager** (main process): queue `queued → generating → normalizing → review`, cancel, timeout (120 s, verified needed), retry, concurrency 1 per provider; spend meter + monthly cap; every job logged with model/params/duration.
   213→   213→
   214→   214→### 3.2 Generation flow (candidates, never silent replace — v1 principle, verified implemented, kept)
   215→   215→1. Prompt (+ recipe preset: size, palette, style tags, seed, provider) → 2. generate N thumbnails (n=1–4 when supported; else N jobs) → 3. pick → full-res → 4. **normalize v2** → 5. review dialog (original vs normalized, zoom, re-run with tweaks) → 6. **Import as layer / as new frame / discard** (prototype's three actions, kept verbatim).
   216→   216→- **Cache**: `hash(recipe + seed + model + prompt)` → hits cost nothing; generation history persisted per project (thumbnails + provenance), restorable.
   217→   217→- **Cost controls**: pre-flight estimate ("≈ $0.04 · gpt-image-1"), monthly cap with hard stop, "dry run" showing the exact prompt.
   218→   218→
   219→   219→### 3.3 Deterministic normalize pipeline v2 (replaces prototype's contain-fit NN)
   220→   220→Order matters; each step pure & unit-testable (golden-image tests):
   221→   221→1. **Trim** to content bbox (alpha/color border flood).
   222→   222→2. **Dominant-color grid downscale** to target WxH: per target cell take the modal color of the source block (center-weighted, ties → closest to block mean). *Why not plain NN (prototype):* NN aliases detail into noise on downscale >2×; dominant-color yields clean sprite reads. (A/B test gated in P1, §9 benchmarks.)
   223→   223→3. **Alpha threshold** (<128 → 0) + **despeckle** (remove isolated single opaque px).
   224→   224→4. **Background removal**: border flood-fill with tolerance (prototype algorithm, kept, already good).
   225→   225→5. **OKLab quantize** to project palette (or auto median-cut ≤64 when "free palette"); dithering **off** by default.
   226→   226→6. Optional 1-px outline cleanup (remove AA fringe: out-of-palette px adjacent to transparency).
   227→   227→All steps run off the main thread (Worker). Provider-independent ⇒ identical output across providers, free to re-run. The <128 alpha threshold here is the same binary-alpha rule the motion composer relies on (§4.1.1 R3).
   228→   228→
   229→   229→### 3.4 Provenance
   230→   230→Every candidate stores `{model, providerId, prompt, seed?, params, timestamp, jobDurationMs}` — shown in review UI, persisted in project file (`provenance/ai/`), reused by "regenerate similar."

   234→   234→## 4 · AI animation — realistic workflow
   235→   235→
   236→   236→> Preserved from v1.0: no promise of one-prompt production animation. **Mechanism below is the v3 addition; composition semantics formalized in v3.1 (C14/C15).**
   237→   237→
   238→   238→### 4.1 Tier 1 — Part-based motion presets (flagship, P1)
   239→   239→- Character = base sprite; optional **part tags** (head/body/armL/armR/legL/legR) via marquee → "Tag part" (stores region, not a cut). Parts may also be separate layers (AI can generate part variants) — a part with no `rect` spans its whole layer.
   240→   240→- Parts serialize at **clip scope** (`clip.parts[]`, C4): `{ id, name, layerId, rect?, anchorFrameId, z }`; array order = paint order (z override optional). Tagging warns when the new region overlaps an existing part.
   241→   241→- Presets = parametric transform curves per part, composed into new cels:
   242→   242→| Preset | Frames | Curve (32×32 reference, scales per C15) |
   243→   243→|---|---|---|
   244→   244→| idle-bob | 4 | body dy = [0,−1,−2,−1]; head dy = body; hair/coat 1-frame lag |
   245→   245→| walk | 4/6/8 | legL/legR alternate dx ±3, dy [0,−1]; body bob dy [0,−1,0,1]; arm counter-swing |
   246→   246→| run | 6 | walk amplitude ×1.5, forward lean dx +1, dy arc |
   247→   247→| attack | 4–6 | armL arc keyframes (raise→swing→recover), 1-px smear frame option |
   248→   248→| jump | 6 | dy parabola, squash [1,2] px on takeoff/land |
   249→   249→- **Composition is undoable, deterministic, $0**; every generated frame remains a normal editable cel; presets can be re-applied/re-parameterized ("amplitude", "hold frames", `gapFill`).
   250→   250→- Verification hooks: side-by-side before/after, per-frame diffs.
   251→   251→
   252→   252→#### 4.1.1 Composition semantics (v3.1, C14/C15)
   253→   253→The composer is a pure function `(sourceCel, parts, preset, params, frameIndex) → cel` — golden-tested, runs in core with zero DOM. **Absent parts**: preset curves referencing part names that are not tagged on the clip are silently skipped for that part (e.g., idle-bob's "hair 1-frame lag" is a no-op on a head/body-only farmer); the apply report lists every skipped part (C27).
   254→   254→
   255→   255→- **R1 · Paint order**: process parts bottom→top (parts array order / `z`). For each part: (a) **cut** its owned pixels from the working canvas (set transparent), (b) apply the frame's integer offset, (c) **paste** back. Later (higher-z) parts therefore always win overlaps — head covers body at the neck, arms cover torso.
   256→   256→- **R2 · Ownership**: a pixel belongs to exactly one part — the **highest-z part whose rect contains it** (assigned at tag time; the tag tool warns on overlap). Lower parts never move pixels they don't own, so overlaps never double-draw.
   257→   257→- **R3 · Transparency**: alpha **≥ 128 = opaque** (moves with the part); alpha < 128 = transparent (stays cleared). This matches normalize v2's binary-alpha threshold (§3.3 step 3); AI-generated or hand-painted semi-alpha px are thresholded by the same rule before composition.
   258→   258→- **R4 · Bounds & gaps**: offsets are **integer pixels**; translated regions are **clipped at the canvas edge** (pixels pushed outside are dropped — no wrap; wrap remains Move-tool-only). Pixels vacated by a part's move are handled by the preset's `gapFill` mode: **`none` (default)** leaves them transparent (honest draft; artist touches up — consistent with "presets propose, humans approve"), **`edge-extend`** fills the entire vacated strip by **repeating the trailing boundary row/column** of the pasted region until the hole is closed (1–3 px at reference amplitudes — prevents see-through slivers on bob/walk/run).
   259→   259→- **R5 · Frame alignment**: every generated frame derives from the **anchor/reference frame** (default frame 1; `anchorFrameId` per part). The same absolute rects and per-frame offsets are used for every output frame, so frames cannot drift apart. Existing per-frame pixel variation is intentionally *not* preserved by presets — that is Tier-2's job (§4.2). Output frames are full replacements of the target cels.
   260→   260→- **R6 · Frame-count reconciliation**: targeting a **new clip** → sized exactly to the preset (4/6/8). Overwriting an existing clip with `overwrite: true` → if the clip has fewer frames, missing frames are appended as holds of the reference; if more, extra frames are left untouched. Either way it is one undoable command.
   261→   261→- **R7 · Timing**: generated cels get `durationMs: 0` → inherit clip fps (consistent with §2.6). Loop behavior follows the clip's `loop`/`loopMode` (C3).
   262→   262→- **R8 · Linked cels**: presets **skip linked layers** (a pinned background must not bob). If a part explicitly targets a linked layer, applying the preset **unlinks** it first (recorded in the same undo entry).
   263→   263→- **R9 · Static remainder**: pixels outside all part rects are **bit-identical** to the source frame — presets never repaint what they don't move (makes per-frame diffs and the flicker detector meaningful).
   264→   264→- **R10 · Cross-canvas scaling (C15, C25)**: `ampScale = clipHeight / 32`; each non-zero curve value v maps to `sign(v) · max(1, |round(v × ampScale)|)` px — magnitude floor 1 px, **direction preserved** (a bob never flips into a sag at 16×16). A 16×16 farmer still visibly bobs (1 px), a 64×64 one moves 2–4 px, matching the reference feel.
   265→   265→
   266→   266→### 4.2 Tier 2 — AI frame variations (P2, review-gated)
   267→   267→img2img: frame N as init (strength 0.25–0.45, seed locked, recipe attached) → normalize v2 → **pixel-diff overlay vs frame N** → user accepts/edits/discards. Suited to breathing/blink/tail-wag deltas. Never auto-chained without review.
   268→   268→
   269→   269→### 4.3 Tier 3 — Experimental (P3, flagged)
   270→   270→Video-model → pixelize pipelines; dedicated pixel-animation services. Behind "Experimental" settings flag; excluded from marketing claims.
   271→   271→
   272→   272→### 4.4 Consistency QA tools (P1)
   273→   273→- **Reference lock**: pin frame 1 as ghost + baseline guide + facing arrow; every new frame request auto-attaches it.
   274→   274→- **Flicker detector**: per-frame pixel-diff heatmap + "jitter score" (changed-px count vs threshold); failing frames highlighted in timeline. Because of R9, diff noise from the composer itself is zero — detected flicker is real content flicker.
   275→   275→- **Anchor overlay**: ground line + center axis; onion skins (§2.6).
   276→   276→- **Review workflow**: animation strip view with per-frame accept/revert; nothing enters the clip without explicit commit.
