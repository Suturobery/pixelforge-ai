   189→### 3.1 Provider adapter (evolved from prototype's verified adapter)
   190→```ts
   191→interface AIProvider {
   192→  id: string; kind: 'zai'|'openai-compatible'|'anthropic'|'local'
   193→  capabilities: { img2img: boolean; seed: boolean; mask: boolean; n: boolean }

   195→  editImage?(req: EditRequest): Promise<GenResult> // img2img / inpaint when supported

   199→- **API key storage (C13 — exact mechanism):** keys live only in the **main process**. Renderer submits a key once via bridge (`settings.setApiKey`); main encrypts with **Electron `safeStorage`** (DPAPI on Windows, Keychain-backed on macOS, libsecret/kwallet on Linux) and persists **base64 ciphertext** as `apiKeyEnc` in the settings file. Plaintext is never written to disk and never returned to the renderer — the bridge exposes only `settings.hasKey(providerId)` (boolean) and `settings.removeKey`. If `safeStorage.isEncryptionAvailable()` is false (e.g., Linux without a keyring service), keys are kept **in memory for the session only** with a persistent warning — no plaintext disk fallback. The web prototype's plaintext localStorage keys are **not** auto-imported (different app; one-time re-entry). Job runner decrypts in memory per request.
   200→- **Job manager** (main process): queue `queued → generating → normalizing → review`, cancel, timeout (120 s, verified needed), retry, concurrency 1 per provider; spend meter + monthly cap; every job logged with model/params/duration.
   201→
   202→### 3.2 Generation flow (candidates, never silent replace — v1 principle, verified implemented, kept)
   203→1. Prompt (+ recipe preset: size, palette, style tags, seed, provider) → 2. generate N thumbnails (n=1–4 when supported; else N jobs) → 3. pick → full-res → 4. **normalize v2** → 5. review dialog (original vs normalized, zoom, re-run with tweaks) → 6. **Import as layer / as new frame / discard** (prototype's three actions, kept verbatim).
   204→- **Cache**: `hash(recipe + seed + model + prompt)` → hits cost nothing; generation history persisted per project (thumbnails + provenance), restorable.
   205→- **Cost controls**: pre-flight estimate ("≈ $0.04 · gpt-image-1"), monthly cap with hard stop, "dry run" showing the exact prompt.
   206→
   207→### 3.3 Deterministic normalize pipeline v2 (replaces prototype's contain-fit NN)
   208→Order matters; each step pure & unit-testable (golden-image tests):
   209→1. **Trim** to content bbox (alpha/color border flood).
   210→2. **Dominant-color grid downscale** to target WxH: per target cell take the modal color of the source block (center-weighted, ties → closest to block mean). *Why not plain NN (prototype):* NN aliases detail into noise on downscale >2×; dominant-color yields clean sprite reads. (A/B test gated in P1, §9 benchmarks.)
   211→3. **Alpha threshold** (<128 → 0) + **despeckle** (remove isolated single opaque px).
   212→4. **Background removal**: border flood-fill with tolerance (prototype algorithm, kept, already good).
   213→5. **OKLab quantize** to project palette (or auto median-cut ≤64 when "free palette"); dithering **off** by default.
   214→6. Optional 1-px outline cleanup (remove AA fringe: out-of-palette px adjacent to transparency).
   215→All steps run off the main thread (Worker). Provider-independent ⇒ identical output across providers, free to re-run. The <128 alpha threshold here is the same binary-alpha rule the motion composer relies on (§4.1.1 R3).

   218→Every candidate stores `{model, providerId, prompt, seed?, params, timestamp, jobDurationMs}` — shown in review UI, persisted in project file (`provenance/ai/`), reused by "regenerate similar."

   222→## 4 · AI animation — realistic workflow
   223→
   224→> Preserved from v1.0: no promise of one-prompt production animation. **Mechanism below is the v3 addition; composition semantics formalized in v3.1 (C14/C15).**
   225→
   226→### 4.1 Tier 1 — Part-based motion presets (flagship, P1)
   227→- Character = base sprite; optional **part tags** (head/body/armL/armR/legL/legR) via marquee → "Tag part" (stores region, not a cut). Parts may also be separate layers (AI can generate part variants) — a part with no `rect` spans its whole layer.
   228→- Parts serialize at **clip scope** (`clip.parts[]`, C4): `{ id, name, layerId, rect?, anchorFrameId, z }`; array order = paint order (z override optional). Tagging warns when the new region overlaps an existing part.
   229→- Presets = parametric transform curves per part, composed into new cels:
   230→| Preset | Frames | Curve (32×32 reference, scales per C15) |
   231→|---|---|---|
   232→| idle-bob | 4 | body dy = [0,−1,−2,−1]; head dy = body; hair/coat 1-frame lag |
   233→| walk | 4/6/8 | legL/legR alternate dx ±3, dy [0,−1]; body bob dy [0,−1,0,1]; arm counter-swing |
   234→| run | 6 | walk amplitude ×1.5, forward lean dx +1, dy arc |
   235→| attack | 4–6 | armL arc keyframes (raise→swing→recover), 1-px smear frame option |
   236→| jump | 6 | dy parabola, squash [1,2] px on takeoff/land |
   237→- **Composition is undoable, deterministic, $0**; every generated frame remains a normal editable cel; presets can be re-applied/re-parameterized ("amplitude", "hold frames", `gapFill`).
   238→- Verification hooks: side-by-side before/after, per-frame diffs.
   239→
   240→#### 4.1.1 Composition semantics (v3.1, C14/C15)
   241→The composer is a pure function `(sourceCel, parts, preset, params, frameIndex) → cel` — golden-tested, runs in core with zero DOM.
   242→
   243→- **R1 · Paint order**: process parts bottom→top (parts array order / `z`). For each part: (a) **cut** its owned pixels from the working canvas (set transparent), (b) apply the frame's integer offset, (c) **paste** back. Later (higher-z) parts therefore always win overlaps — head covers body at the neck, arms cover torso.
   244→- **R2 · Ownership**: a pixel belongs to exactly one part — the **highest-z part whose rect contains it** (assigned at tag time; the tag tool warns on overlap). Lower parts never move pixels they don't own, so overlaps never double-draw.
   245→- **R3 · Transparency**: alpha **≥ 128 = opaque** (moves with the part); alpha < 128 = transparent (stays cleared). This matches normalize v2's binary-alpha threshold (§3.3 step 3); AI-generated or hand-painted semi-alpha px are thresholded by the same rule before composition.
   246→- **R4 · Bounds & gaps**: offsets are **integer pixels**; translated regions are **clipped at the canvas edge** (pixels pushed outside are dropped — no wrap; wrap remains Move-tool-only). Pixels vacated by a part's move are handled by the preset's `gapFill` mode: **`none` (default)** leaves them transparent (honest draft; artist touches up — consistent with "presets propose, humans approve"), **`edge-extend`** duplicates the trailing boundary row/column of the pasted region into the hole (max 1 px, prevents see-through slivers on bob/walk).
   247→- **R5 · Frame alignment**: every generated frame derives from the **anchor/reference frame** (default frame 1; `anchorFrameId` per part). The same absolute rects and per-frame offsets are used for every output frame, so frames cannot drift apart. Existing per-frame pixel variation is intentionally *not* preserved by presets — that is Tier-2's job (§4.2). Output frames are full replacements of the target cels.
   248→- **R6 · Frame-count reconciliation**: targeting a **new clip** → sized exactly to the preset (4/6/8). Overwriting an existing clip with `overwrite: true` → if the clip has fewer frames, missing frames are appended as holds of the reference; if more, extra frames are left untouched. Either way it is one undoable command.
   249→- **R7 · Timing**: generated cels get `durationMs: 0` → inherit clip fps (consistent with §2.6). Loop behavior follows the clip's `loop`/`loopMode` (C3).
   250→- **R8 · Linked cels**: presets **skip linked layers** (a pinned background must not bob). If a part explicitly targets a linked layer, applying the preset **unlinks** it first (recorded in the same undo entry).
   251→- **R9 · Static remainder**: pixels outside all part rects are **bit-identical** to the source frame — presets never repaint what they don't move (makes per-frame diffs and the flicker detector meaningful).
   252→- **R10 · Cross-canvas scaling (C15)**: `ampScale = clipHeight / 32`; each non-zero curve value maps to `max(1, round(value × ampScale))` px — a 16×16 farmer still visibly bobs (1 px), a 64×64 one moves 2–4 px, matching the reference feel.
   253→
   254→### 4.2 Tier 2 — AI frame variations (P2, review-gated)
   255→img2img: frame N as init (strength 0.25–0.45, seed locked, recipe attached) → normalize v2 → **pixel-diff overlay vs frame N** → user accepts/edits/discards. Suited to breathing/blink/tail-wag deltas. Never auto-chained without review.
   256→
   257→### 4.3 Tier 3 — Experimental (P3, flagged)
   258→Video-model → pixelize pipelines; dedicated pixel-animation services. Behind "Experimental" settings flag; excluded from marketing claims.
   259→
   260→### 4.4 Consistency QA tools (P1)
   261→- **Reference lock**: pin frame 1 as ghost + baseline guide + facing arrow; every new frame request auto-attaches it.
   262→- **Flicker detector**: per-frame pixel-diff heatmap + "jitter score" (changed-px count vs threshold); failing frames highlighted in timeline. Because of R9, diff noise from the composer itself is zero — detected flicker is real content flicker.
   263→- **Anchor overlay**: ground line + center axis; onion skins (§2.6).
   264→- **Review workflow**: animation strip view with per-frame accept/revert; nothing enters the clip without explicit commit.

   290→### 5.2a Escalation rules (new, C7)
   291→A small class of L1 operations **escalate to an approval card based on document state**:
   292→- `open_project` / `create_project` when the active project is **clean** → auto (L1).

   295→This keeps "read" honest (reads can never lose work) without making document switching unergonomic for agents.
